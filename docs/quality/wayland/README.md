# Wayland smoke matrices — evidence tracker (#13)

The Wayland parity gate (REQUIRED-BEFORE-PARITY, issue
[#13](https://github.com/acailic/SayItErmano/issues/13)): one dated directory per session holds the
harness evidence (`results.json` = latest run, `report.md` =
append-only journal with the MANUAL checklist the owner
ticks). This README is the summary table, generated by
`scripts/wayland_smoke.py --init` — regenerate it after every
committed run; never edit it by hand. Row definitions and the
exact invoke line per row: [wayland-smoke-matrix.md](../../dev/wayland-smoke-matrix.md).

## Owner workflow (per session: GNOME Wayland first, then sway; X11 on the same build)

1. Enable a real Wayland login (GDM: `WaylandEnable=true` in `/etc/gdm3/custom.conf` + restart GDM, or boot the sway VM) and log into the session.
2. Run `python3 scripts/wayland_smoke.py` — one command; it records the evidence beside this page and prints the plan. Exit 1 means a red row.
3. Tick the MANUAL rows in the recorded `report.md`; work the session's context matrix (A on GNOME Wayland, B on sway, C on X11) from the runbook.
4. Regenerate this table (`python3 scripts/wayland_smoke.py --init`) and commit the evidence tree.

## Red-row policy

Every FAIL row must become either a fix or a known-issues entry users can find — until then this gate stays red. When evidence lands, `docs/STATUS.md` and the Flathub listing's supported-environments text must match it, and the X11 regression pass on the same build must show zero deltas. Brief: [wayland-matrix-execution.md](../../../requests/wayland-matrix-execution.md) (OPEN).
