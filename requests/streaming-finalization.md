Streaming finalization pass - engine-agnostic rewrite of the live pipeline so the preview stops re-decoding the whole take and immediate-stop becomes possible. Roadmap links these explicitly: the spoken-send row notes "Immediate-stop countdown needs streaming VAD", and docs/UPSTREAM-TRACKING.md lists Parakeet Realtime / Nemotron streaming as the unlock for "tighter live preview". This request is the FIRST phase of that story only: segmented finalization on the existing whisper/parakeet backends. True streaming engines (NeMo/Riva, community streaming exports) stay out - the segmented rewrite is the right foundation regardless of which engine lands later, and it is dependency-free. Today: the live preview (fluidvoice/preview.py + the daemon's rolling pass, ~1.2 s cadence per docs/STATUS.md) transcribes a growing raw-PCM buffer from the take's start on every pass - decode cost grows with take length, so long takes get progressively laggier, and there is no notion of finalized segments; the final transcript comes from one full re-decode at stop. There is no VAD gate: silence at the tail still waits for the human to stop.

Scope:
1) Segmenter: fixed-window segmentation of the raw PCM stream (2.0 s windows, 50% hop - planner verifies against whisper chunking practice) with incremental decode per new hop and a small rolling context (last finalized segment's text passed as initial_prompt where the backend supports it; verify per backend in fluidvoice/backends/). Finalized = a window older than one hop that will never change; the preview renders finalized text as stable + the live tail in the existing shimmer style (overlay.py pill unchanged visually except text stability).
2) Cost bound: decode work per tick is now constant (one window), not O(take) - assert this in tests (decode-call counting on a fake backend: N windows -> N decode calls, not N*N/2).
3) Early-stop VAD gate: energy+zero-crossing silence detector on the tail segment (no ML dependency; thresholds configurable, conservative defaults - planner ports threshold values from the existing opt-in silence gate if present in recorder.py/config, cite them); when >= VAD_SILENCE_S (default 2.0) of trailing silence AND at least one finalized non-empty segment exist, the daemon auto-stops with the same path as max-duration auto-stop (watchdog in daemon.py - reuse it). This is "detect silence and finish", NOT the upstream immediate-stop countdown UI - that stays out until the streaming-engine phase, though this unblocks it.
4) Correctness guard: the FINAL transcript at stop must remain a full-take decode over the complete PCM (final quality must not regress to a window-mosaic) - segmentation is a preview+trigger mechanism; the only behavioral change at stop time is earlier stopping on trailing silence. Config: preview.segmented = true (default), preview.segment_s, preview.vad_silence_s; doctor lines.
5) Latency instrumentation: per-take log line (existing log path) with windows decoded, mean decode ms, preview lag at stop - so the before/after is measurable on the daily-driver machine. Plus a first-word-capture regression test (rider from the reviews sweep: upstream's v1.6.6 regression dropped opening words and made the app "unusable"; v1.6.7 got trigger-to-audio under 100 ms): assert the recording start path captures audio from before the first speech boundary - planner verifies what the current Recorder.start() probe path guarantees and pins it with a test so a future refactor cannot silently reintroduce a startup delay or dropped head samples.

Where: fluidvoice/preview.py, fluidvoice/recorder.py (window hand-off if the buffer lives there - planner verifies the raw-PCM ownership), fluidvoice/backends/ (initial_prompt support per backend), fluidvoice/daemon.py (VAD auto-stop wiring onto the existing watchdog), fluidvoice/config.py + doctor.py, tests/test_preview_segmented.py (new: segmentation boundaries, finalize semantics, decode-call bound, VAD trigger table incl. no-trigger-on-all-silence-take, trigger-only-with-nonempty-segment), tests integration/live preview test if one exists (extend).

Done means: a phased plan under specs/ where each phase leaves `.venv/bin/python -m pytest -q tests --ignore=tests/integration` green; on a synthetic long take the fake-backend decode-call count grows linearly, the final transcript equals the full-decode result, trailing-silence takes auto-stop at ~the configured threshold while all-silence takes keep the existing first-PCM/timeout semantics; live smoke on the daily-driver machine logs the instrumentation line with bounded mean decode ms; the upstream tracking table row for immediate-stop notes the new foundation.

Out of scope: NeMo/Riva/streaming-engine integrations, diarization, the immediate-stop countdown UI, changing the final-transcription backends or their quality knobs, multilingual VAD models, any overlay redesign.

Deliverable constraint: the planning phase produces a plan document under specs/ only - planning never edits implementation, config, docs, or test files (the builder phase owns all code changes).
