Idle model unload / keep-warm policy (C-track leapfrog; docs/research/2026-09-05-fluidvoice-reviews.md insight 4: upstream pins ~3.4 GB models in memory forever, freezing 8 GB machines - issue #548 "please stop pretending this is a design choice", discussion #854 - and the maintainer REFUSES time-based unload for latency; #922 asks for a configurable keep-awake window. On Linux with mixed consumer hardware a user-visible policy is a cheap differentiator: upstream will not ship it). SayItErmano today: models stay loaded after first use; warm-up path exists (eager_warmup, warmup() throwaway inference, warm-toggle probe work) - planner verifies where backend instances live and what "unload" means per backend (whisper.cpp process exit, faster-whisper/parakeet model object drop, reference clears + gc).

Scope:
1) Config: model.idle_unload_s (int seconds, default 0 = off) - after this much time with NO dictation activity (last take end OR daemon start with eager warmup counted as activity), release the active model's memory. model.idle_unload_s applies to the active backend only. Validation 30..86400 when non-zero.
2) Lifecycle: a daemon-side idle timer (reset on take start/end and on manual warm-up; NOT reset by preview ticks, history reads, or status polls) fires the unload: drop the backend instance through the existing model-manager seam so the NEXT take re-loads through the existing load path (first-take-after-unload pays load time - that is the documented trade-off; status/doctor show "model: unloaded (idle 12m)"). Re-load trigger: the existing recording-start path (planner verifies the load-on-demand seam; the take must FAIL gracefully, not hang silently, if reload errors).
3) Interaction rules: eager_warmup at daemon start still loads (then the idle timer governs); VAD auto-stop and segmented preview unaffected; if idle_unload_s is 0 everything is byte-identical to today; unload never fires mid-recording or mid-preview.
4) Surfacing: doctor line (policy + current state loaded/unloaded + last activity age), tray tooltip suffix when unloaded, Settings Models page spinbutton (0 = off, minutes display), README one paragraph ("why is my first dictation slow after a break?").
5) Tests: fake backend lifecycle counter - load on first take, no unload while active, unload at threshold with a fake clock, no unload when 0, reload-on-next-take success and error paths, timer not reset by status/preview/history calls, doctor lines.

Where: fluidvoice/config.py, fluidvoice/daemon.py (timer + state), fluidvoice/backends/ or the model-manager seam (planner verifies - model_catalog.py/model_download.py adjacency), fluidvoice/doctor.py, fluidvoice/tray.py, fluidvoice/gtkui/settings_window.py, README.md, tests/test_idle_unload.py (new).

Done means: a phased plan under specs/ where each phase leaves `.venv/bin/python -m pytest -q tests --ignore=tests/integration` green; live smoke on the daily driver with idle_unload_s=60: RSS/VRAM of the daemon drops after ~a minute idle (measure and note the before/after numbers in the spec), next dictation reloads and transcribes correctly, doctor reports both states.

Out of scope: unloading anything but the active model (no pruning of on-disk models - that exists), GPU-specific torch cache tricks beyond dropping the instance, suspend/lock hooks (lockmon owns those), per-backend custom unload code beyond the seam, auto-tuning the threshold.

Deliverable constraint: the planning phase produces a plan document under specs/ only - planning never edits implementation, config, docs, or test files (the builder phase owns all code changes).
