OpenAI-compatible remote STT endpoint as a model backend (C-track leapfrog; docs/research/2026-09-05-fluidvoice-reviews.md insight 12: upstream users beg to point the app at a LAN GPU box serving Whisper Large/Parakeet via an OpenAI-compatible POST /v1/audio/transcriptions endpoint - vLLM/NIM/DGX Spark; the upstream maintainer DECLINED the community's opt-in PR in favor of a native protocol, so this is a differentiator upstream will not ship). SayItErmano is local-first: this adds a user-configured remote backend only - nothing leaves the machine unless the user points at a URL. Wire format: multipart/form-data POST with "file" (wav/flac audio field - planner picks the format the existing recorder pipeline can emit without re-encoding), "model" (string), optional "language"; JSON response {"text": "..."} (accept verbose_json segments if present, concatenate). No streaming in v1: a remote take behaves like a batch backend (preview falls back to the legacy whole-buffer pass or none - planner verifies how batch backends preview today).

Scope:
1) Backend: new remote backend registering alongside the existing model catalog entries: config model.remote_url (empty = off), model.remote_model (name sent in the form), model.remote_api_key (optional bearer; planner verifies how existing provider keys are stored/read and follows the same pattern - never logged, never in doctor output), model.remote_timeout_s (default 30). Request via the HTTP client already vendored/declared if any (planner verifies; otherwise stdlib urllib to avoid a new dependency - state the choice in the spec). WAV preferred if the recorder path already produces it; else flac/opus per what exists.
2) Selection: when remote_url is set, the model-manager/daemon uses the remote backend for dictation (planner verifies the backend-selection seam - likely model_catalog/backends/); a doctor reachability line (configured/unconfigured; when configured, a lightweight GET/HEAD attempt with short timeout, result only - never sending audio in doctor).
3) Error handling: connection refused/timeout/non-200/missing "text" -> user-facing failure through the SAME path as local decode failures (pill error state + log), one retry on transient network errors only, no crash, no infinite retry.
4) Settings/doctor: Models page gains a "Remote (OpenAI-compatible)" row - URL, model name, key (password entry), timeout; doctor matrix line; README gains a short "Remote STT server" section (privacy stance: user-configured endpoint only, LAN-friendly, example vLLM/whisper.cpp server commands).
5) Tests: threaded fake HTTP server (stdlib http.server) asserting the multipart shape (file field non-empty, model field, optional language), returning {"text": ...}; roundtrip through the backend seam; error table (refused, timeout via tiny timeout, 500, malformed JSON, missing text); key never appears in logs/doctor (assert); no-request-when-unconfigured.
